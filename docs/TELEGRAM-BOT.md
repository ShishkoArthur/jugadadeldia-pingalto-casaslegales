# Telegram-бот уведомлений @jpc_avisos_bot — как подключить свой проект

Владелец 05.11: бот пишет **по-русски** и **сразу видно, с каким проектом проблема**. Этот файл можно целиком передать в другой чат:
там агент подключит свой проект к тому же боту и тому же чату, и все сообщения будут выглядеть одинаково.

## 1. Где ключи
- Бот: **@jpc_avisos_bot**. Сообщения идут в личный чат владельца.
- Ключи лежат в `C:devjugadadeldia-pingalto-casaslegales.env` (Windows, Git Bash: `/c/dev/jugadadeldia-pingalto-casaslegales/.env`;
  до 08.11 — `/home/dev/...` на старом сервере; файл под `.gitignore`):
  - `TG_BOT_TOKEN` — токен бота;
  - `TG_CHAT_ID` — id чата владельца.
- **Значения нигде не писать**: ни в код, ни в документы, ни в чат, ни в логи, ни в коммиты. Другой проект копирует обе строки в **свой**
  `.env` (тоже под `.gitignore`), например:
  ```bash
  grep -E '^TG_(BOT_TOKEN|CHAT_ID)=' /c/dev/jugadadeldia-pingalto-casaslegales/.env >> /c/dev/<проект>/.env
  ```
  На сервер — только в файл секретов своего контейнера (`chmod 600`, владелец root), как `secrets.env` здесь.

## 1a. Что считать поломкой автообновления (слать)
- Запуск ленты/задачи упал (исключение, код выхода не 0, источник ответил ошибкой) — с классом причины из таблицы ниже.
- Данные устарели: последнее успешное обновление старше нормы (норму задать на каждую ленту; у нас — `maxAgeH`). Это ловит и случай,
  когда cron/контейнер вообще перестал запускаться: проверку возраста делать **отдельно** от самой ленты (watchdog), иначе мёртвая
  лента о себе не сообщит.
- Источник отдал подозрительные данные (пусто, формат поменялся, расхождение двух источников) — на сайте оставить последние верные.
- Срок чего-то истекает (ключ API, сохранённая копия документа) — 🟡 заранее.
- Починилось — одно 🟢.

## 2. Формат сообщения (общий для всех проектов)
```
🔴 <домен проекта> · лента «<имя>»        ← первая строка, жирным; или «сервис «<имя>»», или просто домен
Что случилось — одной-двумя фразами по-русски.
Причина: класс причины. Источник: <хост>. Технически: <короткая исходная ошибка>
Что сделано: что система уже сделала сама (оставила последние верные данные, скрыла устаревшие цены, ждёт следующего запуска…)
Что делать: обычно «Ничего — исправлю при проверке.» или конкретное действие владельца («Сохранить страницу X из браузера…»)
🕒 05.11 12:30 по Аргентине · 05.11 18:30 по Москве
```
- **Эмодзи важности:** 🔴 сломано (данных нет, сервис не работает, срок истёк) · 🟡 предупреждение (часть данных, скоро истечёт, нужен
  человек) · 🟢 починилось · 🔵 информация. Тестовые сообщения начинаются с `[тест] `.
- **Первая строка — всегда домен проекта** (`jugadadeldia.com`, `pingalto.com`, `casaslegales.com`, у другого проекта — его домен) и через
  ` · ` что именно: `лента «…»` или `сервис «…»`. Так владелец в списке чатов сразу видит, чей сбой.
- Время — по Аргентине и по Москве (владелец пишет по-русски). Если проект не про Аргентину — его часовой пояс и Москва.
- Текст по-русски, без жаргона; техническая причина — коротко, в конце строки «Причина».
- HTML-разметка (`parse_mode: HTML`): только `<b>`, всё подставляемое экранировать (`&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;`).
  Длина — до 4096 символов (мы режем на 4000).

### Классы причин (одни и те же слова во всех проектах)
| Класс | Когда | Текст |
|---|---|---|
| robots | запрет в robots.txt | Сайт-источник запретил доступ роботам (robots.txt) |
| key | HTTP 401, «invalid key» | Источник отклонил наш ключ API (HTTP 401) |
| rate | HTTP 429 | Источник ограничил частоту запросов (HTTP 429) |
| forbidden | HTTP 403 | Источник закрыл доступ нашему серверу (HTTP 403) |
| notfound | HTTP 404/410 | Адреса на источнике больше нет |
| down | HTTP 5xx | Сервер источника отвечает ошибкой (HTTP 5xx) |
| tls | сертификат, TLS | Ошибка защищённого соединения (TLS, сертификат источника) |
| timeout | таймаут | Источник не ответил вовремя (таймаут) |
| network | DNS, соединение | Нет связи с источником (DNS или соединение) |
| format | разбор не прошёл | Источник поменял формат страницы или данных |
| unknown | остальное | Неизвестная ошибка + исходный текст |

### Повторы (чтобы бот не превращался в спам)
- Новая проблема — **одно** сообщение сразу.
- Та же проблема (тот же ключ: лента + вид проблемы) — **не чаще раза в 12 часов**; если она пропала и вернулась в пределах 12 ч —
  молча.
- Пока проблема не исправлена — **одна ежедневная сводка** на проект (все открытые проблемы списком). Напоминания и ранние
  предупреждения о сроках в сводку не входят.
- Починилось — одно 🟢-сообщение (только если о проблеме сообщали).
- Не больше ~8 сообщений за один запуск; остальное — одним сообщением-списком.
- Состояние повторов хранить в файле (у нас — `state/_alerts.json` на сервере), а не в памяти — иначе после перезапуска всё уйдёт заново.
  Если отправка не удалась — состояние не сохранять, чтобы попробовать ещё раз в следующем запуске.

## 3. Минимальный код (Node 18+, без зависимостей)
```js
// telegram.mjs - send one alert; TG_BOT_TOKEN and TG_CHAT_ID come from the env (never print them)
const esc = s => String(s).replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;');
const at = (tz, d = new Date()) => new Intl.DateTimeFormat('ru-RU', { timeZone: tz, day: '2-digit', month: '2-digit', hour: '2-digit', minute: '2-digit' }).format(d).replace(',', '');

export function alertText({ sev, domain, scope, what, why, did, todo }) {
  const emoji = { red: '🔴', yellow: '🟡', green: '🟢', info: '🔵' }[sev] || '🟡';
  return [
    `<b>${emoji} ${esc(domain)}${scope ? ' · ' + esc(scope) : ''}</b>`,
    esc(what),
    why && `<b>Причина:</b> ${esc(why)}`,
    did && `<b>Что сделано:</b> ${esc(did)}`,
    `<b>Что делать:</b> ${esc(todo || 'Ничего — исправлю при проверке.')}`,
    `🕒 ${at('America/Argentina/Buenos_Aires')} по Аргентине · ${at('Europe/Moscow')} по Москве`,
  ].filter(Boolean).join('\n').slice(0, 4000);
}

export async function sendTelegram(text, env = process.env) {
  const tok = env.TG_BOT_TOKEN, chat = env.TG_CHAT_ID;
  if (!tok || !chat) return { ok: false, log: 'telegram not configured' };
  const hide = s => String(s).split(tok).join('***').slice(0, 120);
  let last = '';
  for (let i = 0; i < 3; i++) {
    try {
      const res = await fetch(`https://api.telegram.org/bot${tok}/sendMessage`, {
        method: 'POST', headers: { 'Content-Type': 'application/json' }, signal: AbortSignal.timeout(20000),
        body: JSON.stringify({ chat_id: chat, text, parse_mode: 'HTML', disable_web_page_preview: true }),
      });
      const body = await res.json().catch(() => null);
      if (res.ok && body && body.ok) return { ok: true, log: 'telegram: sent' };
      last = 'HTTP ' + res.status + (body && body.description ? ' ' + hide(body.description) : '');
      if (res.status !== 429 && res.status < 500) break;
      const wait = res.status === 429 && body?.parameters?.retry_after ? Math.min(30, body.parameters.retry_after) * 1000 : 3000;
      await new Promise(r => setTimeout(r, wait));
    } catch (e) { last = hide(e && e.message || e); await new Promise(r => setTimeout(r, 3000)); }
  }
  return { ok: false, log: 'telegram failed: ' + last };
}

//   what: 'Лента «prices» не обновлялась 5 ч; норма — до 3 ч.', why: 'Источник не ответил вовремя (таймаут). Источник: api.example.org.',
//   did: 'На сайте остаются последние верные данные.' }))).log);
```
Важно: в логах печатать только `log` (никогда URL запроса — в нём токен). Если в коде проекта действует правило «без кириллицы в коде»
(как здесь), русские тексты держать в отдельном JSON-файле с шаблонами (у нас — `data/alerts/ru.json`, код — `tools/feeds/alerts.mjs`).

### Одной строкой из shell (cron, watchdog)
```bash
set -a; . ./.env; set +a
curl -sS -m 20 -o /dev/null -w '%{http_code}\n' "https://api.telegram.org/bot${TG_BOT_TOKEN}/sendMessage" \
  --data-urlencode "chat_id=${TG_CHAT_ID}" --data-urlencode "parse_mode=HTML" \
  --data-urlencode "text=<b>🟡 example.com · сервис «backup»</b>
Резервная копия не создана.
```

Не запускать с `set -x` и не печатать саму команду — в ней токен. Ответ `200` — доставлено.

## 4. Как проверить
1. Скопировать ключи в свой `.env` (п. 1).
2. Отправить **одно** тестовое сообщение с префиксом `[тест] `, например:
   `[тест] 🟢 example.com · лента «prices»` + «Проверка уведомлений: бот работает, сообщения проекта example.com приходят в этот чат.»
3. Убедиться, что ответ `200` / `ok: true`, и попросить владельца подтвердить, что сообщение пришло.
4. В тестах кода — подменять отправку (fake `fetch`), реальный Telegram в тестах не вызывать.

Здесь (для справки): `bash tools/feeds-server.sh <сайт> run --test-alert` — тест с сервера; `node tools/feeds/notify.mjs <сайт> <шаблон>
[--feed x|--service x] [ключ=значение…] [--dry]` — одно сообщение по шаблону (`--dry` — только напечатать).

## 5. Ограничения Telegram
- Не чаще **1 сообщения в секунду** в один чат и **не больше 20 в минуту** (иначе HTTP 429 с `retry_after` — подождать столько секунд).
- Сообщение — до 4096 символов.
- Бот не может написать первым: владелец уже нажал /start, `TG_CHAT_ID` — его чат. Новый чат/группа — только по слову владельца.

## 6. Чего НЕ слать
- Секреты: токены, ключи API, пароли, содержимое `.env`, адреса с ключами в query, куки.
- Персональные данные: имена/ники посетителей, IP, e-mail, телефоны, содержимое форм.
- Спам: каждый неудачный запрос, каждую попытку, «всё хорошо» по расписанию, длинные логи и стектрейсы (только короткая причина).
- Сообщения от имени владельца кому-то ещё; ссылки на операторов, рекламу.
- Не менять настройки бота (имя, аватар, вебхуки, команды) и не подключать его к другим чатам без слова владельца.
